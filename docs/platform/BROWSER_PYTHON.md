# M20 local Python replay

Run python scripts/prepare_browser_python.py before building the web application. It stages fixed-version Pyodide 0.29.3 core assets and pydantic/tzdata dependency wheels (upstream SHA256 verified) into ignored public/python-runtime, plus trusted SDK source zip. Build records core and wheel digests; independent core hash pinning/security review still pending. Serve assets same-origin (WASM MIME type and wasm-unsafe-eval CSP if enforcing CSP). No third-party CDN calls at browser runtime. Release bundle must include generated assets.

Local runner available before login, also in Backtest runner after login. Import UTF-8 CSV time,open,high,low,close,volume with contiguous epoch-second UTC opens, max 10080 rows/4 MiB, complete timeframe alignment. Graph JSON or exact generated Python metadata accepted through the existing validator; arbitrary source rejected, never exec/eval. CSV data stays in browser for local run. Both OHLC paths, 1x, user-supplied costs/spec, no funding/liquidation, no external warmup. Summary and month results only. Worker reuse avoids runtime reinitialization on successful reruns; cancel/timeout terminate worker. This worker is a responsiveness boundary, not an arbitrary-code sandbox.

Native/Chromium parity and warm repeat run checked in CI. No full historical cache, parallel pool, custom Python sandbox, multi-year browser runs, mobile benchmark or production deployment yet. M21/M22 extend caching and parallelism after parity is proven.
## M21 cache extension
Input limit raised to 44,640 rows/16 MiB (31 days), same 120s local timeout. Optional IndexedDB keeps one validated CSV per instrument (32 MiB raw maximum; browser quota may be lower); load checks SHA-256 and requires renewed timestamp acknowledgement. No upload or automatic persistence. In a reused worker, parsed candles are cached for one exact CSV hash/instrument; changing either invalidates all indicators. Canonical indicator specs are cached as immutable completed-output sequences (250,000 stored values, plus bounded active series); only the next output is revealed to the simulation when its candle completes. Strategy/risk/cost changes that do not change instrument or indicator specs reuse outputs, while modified specs recalculate. Cached/uncached results must be identical; no future values visible through Context. Reruns still replay orders and balances. Cache lost on worker termination, stored CSV remains. Benchmark native adapter separately from actual browser; no guarantee of full-month completion on mobile. Automatic archive fetching, multiple date partitions, and arbitrary Python remain pending.

## M22 parallel batches
Add the current graph as a snapshot variant, edit each variant independently, and run two to six strategies against identical current CSV, instrument and cost settings. Batch is independent simulations, not portfolio aggregation. Device heuristic caps at two simultaneous runtimes (>=4 reported GB and >=4 logical cores), one if smaller or unknown; user can reduce to one. Each worker keeps only its own M21 cache and reuses it for subsequent queued variants; no cross-worker indicator sharing. Existing idle single-run worker is terminated on batch start, and single-run controls are disabled during batches. Each variant has a 120s timeout and independent status, progress, cancellation and result hashes; failed/cancelled slots terminate; successful slots can be reused. All workers terminate at batch end or component unmount. No data upload, no automatic winner, no guarantee of memory availability or acceleration. Browser test compares two independent real WASM runs against native-Python oracle hashes, checks two active slots, a rejected source, queued cancellation and low-memory cancel-all. Full-month parallel browser performance and mobile RAM benchmarks remain pending.

## M23 quick reruns and experiment history
Name an experiment and edit its graph, then run again. Each successful single or batch run creates an immutable session record (exact source, result hashes, instrument, settings and timing; no CSV or credentials). Retain up to 30 newest records. Explicit save or opt-in remember persists completed runs in IndexedDB; origin-local, not encrypted storage, no cloud sync. Restore copies source/settings but clears mismatched CSV and requires timestamp acknowledgement. Compare a baseline and candidate on the same modeled OHLC path; improvement deltas only if exact CSV hash, instrument, engine version and cost/capital settings match. Numeric comparison is rounded display arithmetic, not execution. Clear experiments does not delete saved CSV or backend strategies. Browser tests cover rerun, persistence, restoration and mismatch guard. Full multi-year local execution remains pending.

## M24 explicit leveraged reference replay
Separate browser risk panel uses current CSV/graph, independent mark CSV time,open,high,low,close, optional funding CSV time,rate,reference_mark with complete specified UTC schedule. User supplies effective margin profile dates and source, initial/maintenance fractions, max notional, liquidation fee bps, leverage (1–100 subject to profile), mode, optional fixed price point buffer. Exposure % refers to equity allocated to initial margin; notional scales with leverage. Mark-first fixed OHLC paths; when maintenance is breached liquidation wins, otherwise buffer may trigger modeled protective close at paired trade vertex, halting the simulation. No guarantee of protection. Optional conservative 30-minute single-entry full-close closing fee waiver requires explicit assumed eligible period; no partial-close or vouchers, no historical offer inference. See Delta official support article 80001172745. Results show fees/tax/funding, liquidations/preliq count and hashed input assumptions. No risk settings stored in ordinary experiment history or parallel batch. Actual exchange rules/settlement and historical inputs not certified. No live orders.

## M25 walk-forward optimization
Use current CSV and graph; enter integer window minutes, optional UTC start (blank uses CSV first row), rolling or expanding mode, 2–4 folds, 2–8 candidate parameter combinations using grid or seeded random. Max 120,000 total replay candidate-minutes before both OHLC paths, 300s timeout per fold; workers use M22 device cap. Each fold independently trains and selects using worst-path objective, max DD/min trades, then evaluates frozen winner on subsequent disjoint test window, with baseline, fee-only, slippage-only, combined and closest evaluated training neighbor. Monthly consistency ranks by minimum positive segment ratio across paths, then minimum monthly segment return, then worst return; partial calendar months count as segments. No holdout-driven winner reselection. Missing eligible winner blocks tests. Test gates are modeled checks, not evidence of true generalization. Full raw CSV is hashed, only window slice is fed to each simulation. No funding/leverage here, no continuous OOS balance or external warmup. Native multi-year research CLI: python -m btc_analysis.service.walkforward_cli --history HISTORY --request request.json --graph graph.json --study study.json --output NEW.json --workers 2. Request is a long historical request, study fields same as browser, warmup zero; max 5M candidate-minutes, temporary per-run archives removed after summaries. CI benchmarks 30d train/7d test, 2 rolling folds on actual BTC/ETH; exact browser parity with deterministic fixture.
