# M17 readiness implementation (not production approval)

API body reception has a 10s deadline, length and fragmentation limits. Request validation responses omit supplied fields. Anti-framing/referrer/resource headers. Worker reads progress incrementally and polls every 200ms. Arbitrary Python execution remains disabled. No live order route.

## Local deployment reference
Use a dedicated Linux host with at least 2 GiB RAM as a starting assumption; benchmark on target. Install release /opt/btc-platform, create dedicated btc-platform user/group, private writable /var/lib/btc-platform (0700), root-owned release files. Install Python package with data,api extras in /opt/btc-platform/venv; build apps/web with npm install and npm run build, copy dist to /opt/btc-platform/web read-only. Import history with M2 CLI to configured history directory. Create root-only /etc/btc-platform/api.env from example with freshly generated token; never deploy placeholder. Install systemd units and nginx snippet after review. Run systemd-analyze verify and nginx -t. Enable API/worker only after validation. SSH tunnel to 127.0.0.1:8080; do not expose publicly. Verify CSP/Monaco behavior through nginx, auth, reference jobs and restore. Optional paper service requires separate operator enablement and feed checks. Non-root services, resource quotas, read-only system paths, private tmp and dropped capabilities are templates, not an audited untrusted-code sandbox.

## Backup and recovery
python -m btc_analysis.service.backup backup --source /var/lib/btc-platform/studio.sqlite --destination /secure-backup/studio-unique.sqlite
Record SHA-256 separately in protected storage. Online SQLite backup includes committed WAL data, integrity and foreign-key checks. New destination only, private mode. Restore to NEW path with restore --source BACKUP --destination NEW_DB --sha256 HASH. Verify result and switch service config only after stopping all workers/API/paper poller. Interrupted queued/cancelling jobs cancelled, running jobs failed, active paper sessions halted; completed results and immutable revisions preserved. Never overwrite existing DB. DB backup excludes Parquet/bundles, release/config/secrets: retain pinned snapshots and back them up separately. Offsite encrypted retention, scheduled backups and actual disaster recovery drill pending.
