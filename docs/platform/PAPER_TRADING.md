# M15 bounded forward candle paper sessions

Run the existing API, and separately on the same SQLite DB: python -m btc_analysis.service.paper --db "$BTC_PLATFORM_DB". This process uses only the fixed public HTTPS GET endpoint documented at https://docs.delta.exchange/ (history/candles), no exchange keys or order routes. No worker is deployed automatically.

Owner-scoped create/list/get/stop API, idempotent session creation, frozen intact visual revision required, one active per owner/four total. Separate virtual accounts, duration 1–120 minutes aligned to declared frames (1m execution, combined alignment <=15m). Start strictly in future; no warmup. Capture each exact minute after close +10s and within 120s of close; no stale catch-up. Missing network response retries inside window only, then halts. Raw candle labels assumed opens, not independently attested. Durable immutable captured rows and receipt timestamps, CAS transaction for progress/stop; restart resumes only if next bar still fresh. Archived strategy stops on next update. One process recommended, duplicate polls fenced. No credentials or live order code.

Checkpoint recomputes bounded captured prefix at aligned boundaries with the same reference engine and two independent OHLC paths; previous recorded fills must match prefix. This is forward-collected candle simulation, not real-time tick matching, no historical warmup, no actual spread/funding/liquidation, no leverage beyond 1x. Drawdown gate at checkpoint stops session; it does not flatten modeled open positions. Final open positions and unrealized P&L retained. No implicit replay beyond recorded bars. API/UI show virtual balance/equity, position, P&L, drawdown, fills and session history. No automatic backtest comparison or multi-day sessions. Tests use injected public-feed responses/clock; real network feed and live VPS operation remain unverified. Production approval requires independent execution comparison and risk review.
