# M9 visual Python strategy builder

The Studio now has a visual builder for bounded typed rules. Choose candle fields, constants or canonical SDK indicator outputs with parameters and timeframe; compare using inequalities/equality or crossover/crossunder. Each entry/exit rule combines groups with AND/OR; each group combines up to eight conditions. Enable long and short entries/exits independently. Reorder up to four groups by drag/drop or accessible arrow buttons. Set signal/execution timeframes, notional equity exposure and percentage stop/target.

Authenticated POST /v1/visual/compile validates a strict graph and emits deterministic readable Python subclassing the common PythonStrategy SDK through VisualStrategyBase. Canonical parameters/defaults and graph SHA-256 are recorded; metadata header is inert base64 of the canonical graph. POST /v1/visual/recover accepts only byte-identical regeneration from that header. Edited Python stays in code mode. Save generated source using normal immutable revisions; reopen it visually or open saved source in Monaco. No arbitrary source execution route is enabled. The compiler emits fixed SDK calls and validated literals, never evaluates expressions or imported source. Tests execute compiler-generated trusted fixture code only to compare it with a handwritten reference on synthetic candles.

Semantics: one net position, no pyramid, simultaneous long/short signal skips, entries and rule exits at next eligible execution open. Risk orders are reduce-only and submitted after the entry-fill callback at candle close, so the entry candle is **not protected**; the engine cancels stale reduce-only orders when flat. Tick rounding and full-fill assumptions documented in M3 still apply. Exposure is notional percentage of equity, not leverage multiplier. Stop/target 0.01–99%, exposure 0.01–100%. Cross conditions use the configured signal timeframe to avoid reusing a stale crossing on a faster clock. Other comparisons use completed bars only. Runner must bind graph signal/execution timeframes when historical jobs become available. This is a rule-card builder with draggable groups, not a general arbitrary-node graph canvas or reverse compiler. Trailing stops, custom indicator functions, partial exits, leveraged sizing and execution of uploaded strategies are deferred. Production deployment, real-data verification and independent review remain pending.

## Phase 1C: advanced visual controls
An optional `advanced` block extends v1 without changing existing canonical sources or graph hashes when absent. Both local and Cloud builders expose independent entry frequency (continuous or one filled entry per contiguous true run per direction), consecutive completed-signal confirmations, cooldown signal candles after a full exit, IST weekday entry selection, and fixed price-point or percentage exit units. Entry rules are evaluated on each completed signal even with an open position, and the cycle is consumed only on a filled entry. Ambiguous simultaneous raw signals are skipped. Exits are not weekday-restricted. Fixed-point bracket uses the generic same-entry-minute engine, exact tick multiples, single market entry and two modeled paths. Percentage exits retain original timing. Both generated Python and graph replay share the same generic runtime. No strategy-specific logic. Advanced custom indicator selection, explicit reset-rule graphs, trailing stops, and optimizer expansion remain future work.

Phase 1D: in advanced fixed-point exit mode, optionally select trailing activation/distance and profit-lock activation/locked points. Both use the shared engine-managed stop; tighter stop wins. Legacy canonical sources omit absent controls and retain existing hashes. Managed exits require exact tick multiples and existing fixed-point SL/TP; percentage/ATR trailing not implemented. Both OHLC paths are modeled independently; no guaranteed net profit.

Phase 1E-a: optional fixed target disabling, with unchanged stop protection. Walk-forward searches may vary enabled `advanced:` axes (confirmation, cooldown, point stop/target, trailing and profit-lock fields); disabled or inactive axes fail closed. Legacy sources omit absent optional fields. Local API visual search supports these axes as well.

Phase 1E-b: fixed-point initial exit mode supports independent point, percent, or ATR trailing distance. ATR activation is entry gain %, timeframe/period/multiplier are configurable. Percentage activation is entry gain %, distance % of best price. Optional point profit-lock can coexist. ATR/percent fields can be optimized with advanced:trailing_percent.activation/distance and advanced:trailing_atr.activation/period/multiplier; timeframe remains fixed in a study. No future candles used. Legacy percentage initial brackets retain their historical next-minute semantics; dynamic trailing is currently attached to fixed-point initial protection only.

## Phase 1F-a: sequential entries
Optional directional sequences contain 2–4 enabled rule stages, an optional explicit reset rule and expiry in completed signal candles since stage one. A stage advances at most once per candle while flat, and stages need not remain true. Reset takes priority; after expiry the current candle may start a new sequence. Once armed, the ordinary directional entry rule, confirmation, weekday, cooldown, and ambiguity filters still apply. A filled entry clears both sequences; an open position also clears pending sequences. Long and short independent until fill. All stage/reset indicator declarations and timeframes participate in canonical compilation, alignment, and existing indicator optimization. Optimize expiry with `sequence:long.expiry_bars` or `sequence:short.expiry_bars`. Existing visual source remains unchanged when absent. User-defined formula operands are a separate milestone.

### Custom formula operands (Phase 1F-b)

Declare up to 16 unique named formulas with a timeframe, 1–4096 completed-candle lookback and a single expression (512 characters maximum). Examples: `mean(series(bars, "close"))`, `bars[-1].close - bars[0].close`, `bars[-1].close if previous is None else (previous + bars[-1].close) / 2`. Select the named custom formula in any rule or sequence stage/reset. Crossing rules require matching signal timeframes. The interpreter rejects imports, private attributes, context access and unsupported calls; each scenario has private rolling and recursive state. Warmup returns no value until the declared lookback is filled. Use `custom:formula1.lookback` as a walk-forward axis for a formula named `formula1`. Formula outputs are not yet included as result-chart overlays.

Short CSV replay detailed results now include sampled custom formula histories (up to 600 points per declaration and scenario). Select a formula, inspect UTC completed-candle values, and optionally overlay candle close when the formula uses price units. Warmup/null samples remain blank. This is presentation data, not a change to canonical backtest results; long summary replay has no formula chart.

### Directional state machines (Phase 1G-a)

Enable a state machine instead of a linear sequence for each direction. State 0 is idle; the last state arms the existing directional entry condition. Choose 2–8 states and up to 24 ordered conditional transitions. Every state must be reachable, no transitions leave the armed state, and self-edges/duplicate edges are rejected (combine alternatives in a rule). A maximum of one transition is taken per completed signal candle; list order resolves simultaneous true transitions. Global reset and open positions clear progress before transition evaluation. Expiry begins on departure from idle; a return-to-idle transition clears the clock. Entry fills clear both directions. State machine expiry is an optimization axis (`machine:long.expiry_bars` or `machine:short.expiry_bars`). All built-in and custom operands are available; cross-timeframe crossover restrictions still apply. This is an entry gate, not an arbitrary order-action or position-management state machine.
