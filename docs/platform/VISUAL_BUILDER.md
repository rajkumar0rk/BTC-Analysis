# M9 visual Python strategy builder

The Studio now has a visual builder for bounded typed rules. Choose candle fields, constants or canonical SDK indicator outputs with parameters and timeframe; compare using inequalities/equality or crossover/crossunder. Each entry/exit rule combines groups with AND/OR; each group combines up to eight conditions. Enable long and short entries/exits independently. Reorder up to four groups by drag/drop or accessible arrow buttons. Set signal/execution timeframes, notional equity exposure and percentage stop/target.

Authenticated POST /v1/visual/compile validates a strict graph and emits deterministic readable Python subclassing the common PythonStrategy SDK through VisualStrategyBase. Canonical parameters/defaults and graph SHA-256 are recorded; metadata header is inert base64 of the canonical graph. POST /v1/visual/recover accepts only byte-identical regeneration from that header. Edited Python stays in code mode. Save generated source using normal immutable revisions; reopen it visually or open saved source in Monaco. No arbitrary source execution route is enabled. The compiler emits fixed SDK calls and validated literals, never evaluates expressions or imported source. Tests execute compiler-generated trusted fixture code only to compare it with a handwritten reference on synthetic candles.

Semantics: one net position, no pyramid, simultaneous long/short signal skips, entries and rule exits at next eligible execution open. Risk orders are reduce-only and submitted after the entry-fill callback at candle close, so the entry candle is **not protected**; the engine cancels stale reduce-only orders when flat. Tick rounding and full-fill assumptions documented in M3 still apply. Exposure is notional percentage of equity, not leverage multiplier. Stop/target 0.01–99%, exposure 0.01–100%. Cross conditions use the configured signal timeframe to avoid reusing a stale crossing on a faster clock. Other comparisons use completed bars only. Runner must bind graph signal/execution timeframes when historical jobs become available. This is a rule-card builder with draggable groups, not a general arbitrary-node graph canvas or reverse compiler. Trailing stops, custom indicator functions, partial exits, leveraged sizing and execution of uploaded strategies are deferred. Production deployment, real-data verification and independent review remain pending.

## Phase 1C: advanced visual controls
An optional `advanced` block extends v1 without changing existing canonical sources or graph hashes when absent. Both local and Cloud builders expose independent entry frequency (continuous or one filled entry per contiguous true run per direction), consecutive completed-signal confirmations, cooldown signal candles after a full exit, IST weekday entry selection, and fixed price-point or percentage exit units. Entry rules are evaluated on each completed signal even with an open position, and the cycle is consumed only on a filled entry. Ambiguous simultaneous raw signals are skipped. Exits are not weekday-restricted. Fixed-point bracket uses the generic same-entry-minute engine, exact tick multiples, single market entry and two modeled paths. Percentage exits retain original timing. Both generated Python and graph replay share the same generic runtime. No strategy-specific logic. Advanced custom indicator selection, explicit reset-rule graphs, trailing stops, and optimizer expansion remain future work.

Phase 1D: in advanced fixed-point exit mode, optionally select trailing activation/distance and profit-lock activation/locked points. Both use the shared engine-managed stop; tighter stop wins. Legacy canonical sources omit absent controls and retain existing hashes. Managed exits require exact tick multiples and existing fixed-point SL/TP; percentage/ATR trailing not implemented. Both OHLC paths are modeled independently; no guaranteed net profit.
