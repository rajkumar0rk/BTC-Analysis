# M26: lightweight Cloudflare API foundation

No deployment, billing changes, credentials or public endpoints have been created. Worker config disables workers.dev and preview URLs. Cloudflare Free documentation: https://developers.cloudflare.com/workers/platform/limits/ (100,000 requests/day per account, 10ms CPU/request); actual CPU/quotas unmeasured. Heavy Python simulation stays in the browser or GitHub Actions.

The module uses Web APIs only. GET /health is unauthenticated and exposes no account information. Authenticated /v1/cloud/capabilities reports actual features (storage false until M27); strategy list/create/read immutable revision/update CAS contracts require a persistent adapter. M26 production deliberately has none, returns 503; only contract tests inject an in-memory fake. No arbitrary Python execution, exchange orders, job dispatch or paper endpoints. Existing FastAPI and public research dashboard unchanged.

Authentication: operator-generated random 32-byte (43-char unpadded base64url) or longer bearer token, SHA256 digest mapped to owner in AUTH_HASHES_JSON Worker secret. Up to eight distinct owners. Store digest map with Wrangler secret, never commit it or put raw tokens in configuration. Rotate by replacing digest. Exact HTTPS origin allowlist via ALLOWED_ORIGINS; empty by default, up to four. Origin checks not authentication, no credentialed CORS, all private responses no-store, bounded JSON 96 KiB/source 64 KiB. On shared GitHub Pages origin, other sites at that origin have the same origin trust: use an isolated trusted frontend origin for private data and avoid persisting tokens. Browser cloudApi.ts accepts explicit HTTPS origin only, no redirect or storage. UI connection and secure hosted origin integration deferred to M29.

CI runs Node Web API contract tests and pinned Wrangler dry-run bundle; no cloud account access. Wrangler transitive tooling not lockfile-pinned/audited yet; dry run is not actual runtime or CPU verification. M27 implements D1 schema, owner quotas, atomic CAS and integration tests; M28 implements durable paper trading, M29 frontend integration, M30 measured deployment/security. No deployment until authorized account setup and reviewed configuration.

## M27 D1 persistent adapter
Production worker uses env.DB only if explicitly bound; default wrangler.toml still contains no live database ID. Create a D1 database in an authorized account, add [[d1_databases]] binding DB with real database_name/database_id and migrations_dir="migrations", apply migrations after review. wrangler.local.toml is dummy-ID emulator-only, never deploy or use --remote. Owner primary keys, foreign keys, insert triggers and immutable revision triggers enforce quotas and atomic version CAS. Up to 30 strategies, 100 revisions per strategy, 300 total revisions and 200 results per owner, max 8 owners. Approx raw upper bound 150 MiB source + 50 MiB result payload across 8 owners; SQLite/index overhead additional, below free database target only as an estimate. No auto deletion or unlimited retention; results can be explicitly removed, strategy revision deletion reserved for future operator retention workflow. Results are inert bounded typed client-submitted summaries pinned to existing owner strategy revision and source hash, not authenticated simulation evidence; IDs are idempotent for exact payload, different payload conflicts. No candles, credentials or full ledgers uploaded. Indexed owner queries, limited rows, D1 batch for create and single guarded INSERT RETURNING for revision CAS. D1 quota failures return errors, no paid fallback. Local emulator tests use real migration, concurrent revision writes, owner isolation, result validation/idempotency and restart persistence. Live D1 billing, quotas and runtime CPU not measured. Deployment and UI connection pending M29/M30. D1 limits and pricing: https://developers.cloudflare.com/d1/platform/limits/ and https://developers.cloudflare.com/d1/platform/pricing/.

## M28 bounded continuous paper lanes
SQLite-backed PaperLane Durable Object (new_sqlite_classes migration), owner + symbol scoped BTCUSD/ETHUSD, one retained session each. Independent fixed-point 8-decimal long-only 1m EMA crossover reference (not general Python/visual strategy parity), fast 2–99, slow up to 200, first-close EMA seed and slow-period warmup, next-minute open fills reconstructed from completed candles, 1x virtual spot-like account, explicit fee/GST/slippage bps, close-sampled drawdown. No live credentials/orders, no funding/leverage/stop simulation. Public Delta history GET exact one closed 1m candle, timestamp-open assumption unverified, no redirects, bounded response, retries every 15 seconds until stale at 3 minutes from candle open; halt on gaps, preserve open exposure. Alarm rearmed before external fetch; SQLite transaction fences session id/cursor and commits state/fill/alarm atomically. Session 20 minutes or user-configured slow+2 to 10080 minutes (7 days); stop does not flatten. Explicit clear terminal session in 100-fill batches; no silent history deletion. API and browser client added, UI pending. Free DO SQLite support documented https://developers.cloudflare.com/durable-objects/platform/limits/ ; nominal two lanes 2880 normal alarms/day per owner, retries/reads/writes extra, real quota/CPU and Delta connectivity unverified. Node deterministic transition/alarm tests and real local DO lifecycle/restart CI queued. Mock clock/candles in unit tests only; live alarm execution not verified. No deployment.

## M29 UI integration
Public Pages Studio is token-free. Default build has separate private cloud workspace, HTTPS non-github.io guard, explicit connection, immutable revision management, exact-source matching upload of previously saved device-local experiment summaries, inspection/deletion, fixed EMA paper lane controls and paged ledger. Use isolated trusted HTTPS origin, not shared public Pages; server CORS must allow that exact origin. No automatic uploads, no browser token persistence, no claims of server-verified results. Paper refresh is manual; alarm scheduling is server-side. Private frontend hosting, production Worker/D1 provisioning, actual network/CPU/free-tier verification remain M30 work. Public dashboard publisher untouched.
