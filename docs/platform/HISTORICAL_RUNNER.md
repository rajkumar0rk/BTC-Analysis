# M10 bounded historical runner

Import actual archives using M2 (python -m btc_analysis.data.cli --symbol BTCUSD --symbol ETHUSD). Set BTC_PLATFORM_HISTORY to the absolute derived-store directory for both API and worker; restart them. Studio discovers pinned snapshots through GET /v1/datasets. POST /v1/jobs/historical accepts owned immutable visual revisions only, exact dataset digest, UTC evaluation dates, warmup, capital, explicit fees/tax/slippage, and user-assumed tick/lot/multiplier. Server recovers byte-identical compiler graph, validates and pins graph/code fingerprints. The worker invokes a trusted GraphStrategy with the same SDK runtime as generated code; no exec/eval of uploaded source. Actual history is streamed and checksum-checked; gaps fail closed. The worker has time, result-size and virtual-address-space limits; 1440 evaluation minutes plus 1440 warmup minutes, 1m execution, all dates aligned to every requested timeframe. Only 1x linear reference, continuous UTC, two OHLC paths. User must explicitly acknowledge model limitations and unverified open-label assumption if applicable; results remain research-only and distinct from synthetic fixtures. Contract assumptions are editable, not attested venue specifications. Funding, spread, liquidation and leveraged historical jobs are not enabled. Result size quota may reject dense strategies. Multi-year runs, risk input adapters, full arbitrary Python sandbox, historical label attestation, deployment and independent review remain pending. CI tests fixture partition and real BTC archive through actual worker, parity with generated fixture source, ownership, idempotency, and UI integration.
