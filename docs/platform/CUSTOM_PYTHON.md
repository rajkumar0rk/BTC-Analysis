# Independent strategy authoring paths

Cloud Strategies supports visual rules and pasted/edited Python. Both can be saved as immutable owner-scoped revisions and opened in Local backtests. The new Python path requires no metadata header, no source-code generation and no repository changes per compatible strategy. It uses a bounded AST interpreter inside the existing local browser worker, **not arbitrary CPython execution**, no eval/exec or import machinery. No server-side custom code, paper/live integration, external libraries, reflection, filesystem/network, comprehensions, while, recursion beyond eight frames, floating literals or arbitrary attributes. Supported: one class inheriting PythonStrategy; simple SDK imports (decimal, contracts, strategy, indicators); class constants; self state; simple methods and callbacks on_start/on_signal/on_execution/on_fill/on_finish; indicator declarations and extra_timeframes; conditions, bounded for loops, assignments, arithmetic/comparisons, indexing and tuples/dicts, D("decimal"), Timeframe, spec, IndicatorSpec.create, quantity_for_notional, crossover/crossunder, weekday_ist(timestamp), ctx.candles/indicator/indicator_history/equity/position_quantity/instrument/now_utc, buy/sell/order/close_position/cancel. Use ctx.cancel(order_id). Signal_seconds defaults to 60, execution_seconds=60. Exposure fraction defaults to 0.5; self.exposure includes leverage in leveraged replay. fixed_point_bracket=(D("100"),D("200")) optional, requires single market entry, exact tick multiples, entry-minute protection. Without fixed bracket, order protection is authored by script. Unsupported code fails clearly; not a claim of fully general Python compatibility or independent security certification. Source hash pins interpreter version and exact script. Browser worker timeouts remain; callback budget 20k AST operations, 4k AST nodes, bounded values. Both short and long replay use common SDK engine and explicit risk assumptions. Graph-based optimization remains visual only. Visual authoring uses the existing RuleEdit component and local compiler. Existing saved strategies not changed. No authenticated production write performed.

The generic engine has no strategy-specific template registry or runtime dispatch. Standalone source examples in `strategies/cloud/` are not part of the browser runtime package. The Python scaffold contains no trading rules. Fixed-point exit reasons are generic `fixed_point_stop` / `fixed_point_target`; result hashes for previously hardcoded bracket runs may differ. Legacy stored strategy-specific wrappers must be replaced with ordinary SDK source; stored revisions are not mutated.

## Phase 1A: validation and editable parameters
The local worker validates exact visual source/JSON or SDK Python, checks every direct call including inactive branches, reports syntax/SDK/initialization diagnostics with line/column, and identifies declared frames/indicators. Runtime expression errors include source lines. Cloud editor Save runs this validation and prevents invalid source saves via that UI (direct Cloud API still intentionally stores inert text). The local runner also has validation controls. `period = parameter(20, 2, 100)` or `distance = parameter(D('100'), D('10'), D('500'))` declares a bounded immutable numeric class parameter, maximum 32. The UI edits only the literal default using AST byte offsets, revalidates, and uses exact edited source in all existing replay/registry hashes; no hidden override or strategy-specific code. Execution settings retain their existing controls. Callback semantics are not proven by initialization validation; no full Python sandbox certification, custom indicator language, or Python optimizer yet.

## Phase 1B: custom indicator formulas
Declare `custom_indicators(self)` returning a tuple of up to 16 `(name, Timeframe(seconds), lookback, 'formula_method')` declarations. Implement each method as `def formula(self, bars, previous):` and return a finite Decimal/integer or None. Each indicator receives a bounded tuple of 1–4096 completed candles at its own declared timeframe, only after its lookback fills, and its prior output (None until initialized). `series(bars, 'close')`, `sum(values)`, `mean(values)`, `stddev(values)` (population), `sqrt(value)` and existing arithmetic provide bounded Decimal calculations. Formulas may read immutable scalar class constants/parameters and call pure helpers; they cannot access trading context, orders, other indicator histories or mutable trading state, or write self fields. Every formula updates exactly once per completed bar, including engine warmup, independently per OHLC path. Call `self.custom_value(name)` or `self.custom_history(name, limit=2)` in strategy callbacks; history is bounded to 4096 and includes None during initialization. Built-in indicator API unchanged. User-defined indicator metadata is displayed in validation; formula outputs are not yet charted, shared between strategies or selectable in Visual Builder. No arbitrary imports or external libraries. All strategy-specific formulas reside in source, not in the engine.
