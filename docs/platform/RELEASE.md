Public M29 deployment 45813186358 passed; URL https://rajkumar0rk.github.io/BTC-Analysis/studio/. Native foundation and browser CI also passed at 3a78fdc. Static package ~18 MiB. Research-only, not approved for real trades.

## Authorized operator setup (not performed by CI)
1. Confirm Cloudflare Workers Free plan in your own account; do not upgrade to paid. Ensure workers.dev subdomain. Use a trusted local terminal, not chat, to run `npx --yes wrangler@4.157.0 login` and `npx --yes wrangler@4.157.0 whoami`.
2. In apps/cloud, create a D1 database via `npx --yes wrangler@4.157.0 d1 create btc-analysis`; record its ID. Do not reuse an unrelated DB. No secrets in Git.
3. At repo root run `python scripts/prepare_browser_python.py`; in apps/web run `npm ci && npm run build -- --mode private`. From root use `python scripts/prepare_cloud_release.py --worker btc-analysis --origin https://btc-analysis.YOUR-SUBDOMAIN.workers.dev --database-id YOUR-DB-UUID` (replace placeholders). Review ignored generated apps/cloud/wrangler.release.toml. Paper remains disabled.
4. In apps/cloud, run `npx --yes wrangler@4.157.0 deploy --config wrangler.release.toml --dry-run`. Review output and asset bundle. Apply reviewed migration using `npx --yes wrangler@4.157.0 d1 migrations apply DB --remote --config wrangler.release.toml`. Deploy only after verifying the account and config: `npx --yes wrangler@4.157.0 deploy --config wrangler.release.toml`. Auth remains fail-closed until a secret is configured.
5. Generate a high entropy bearer token locally, store it in a password manager. Compute its SHA256 hex digest locally. Set AUTH_HASHES_JSON (JSON object mapping your chosen owner to digest) with `npx --yes wrangler@4.157.0 secret put AUTH_HASHES_JSON --config wrangler.release.toml` interactively. Never send a raw token or account credentials to chat or commit them. Verify unauthenticated capabilities 401, own authenticated capabilities, exact origin, create/update/CAS/owner access and saved result roundtrip. No live order routes.
6. Review runtime analytics and D1 row metrics. Only after checking free allowance and actual Delta public data availability, edit PAPER_ENABLED to "true" and redeploy on same namespace; start a short virtual session and observe cursor/ledger for at least one hour. Stop on gaps; disabling switch halts active alarms on next invocation. Stop explicitly before disabling. Do not claim exchange parity.

## Budget assumptions, not measured
Workers Free 100k requests/day and 10ms Worker CPU/request; D1 5M rows read, 100k written/day and 5 GB total; SQLite DO 100k requests/day, 13k GB-s/day, 5M reads/100k writes per day and 5 GB total. See https://developers.cloudflare.com/workers/platform/pricing/ and https://developers.cloudflare.com/durable-objects/platform/pricing/ . Two lanes nominal 2880 alarms/day; normal processing ~3 storage writes/closed minute plus fills and start/stop. Retries increase duration and writes; 8s market timeout can use substantial GB-s; runtime/idle behavior, actual row accounting and other account workloads must be measured. No paid fallback. Free tier may reject invocations on exhaustion. 7-day paper limit is intentional; no unattended live trading.
