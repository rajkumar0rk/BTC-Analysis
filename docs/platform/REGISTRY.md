# M12 strategy registry

Additive SQLite migration creates strategy_registry and registry_events; existing strategies receive editable metadata and all original source/jobs remain. Revisions immutable. Freeze latest is permanent, records exact version/hash and blocks further revisions, permits only frozen version for new historical jobs. It does not validate strategy performance. Archive blocks edits/new submissions, preserves existing queued/running jobs and results; restore preserves frozen state. Idempotent retries of earlier submissions remain valid. Lifecycle transitions require expected head and state revision, checked transactionally; submit checks ownership, archive/freeze and pinned revision hash in same transaction as enqueue. Clone any saved revision, including archived/frozen, creates editable version 1 with exact parent source hash and lineage; no copy of prior performance.

Authenticated version history, lifecycle transitions, clone, and paginated linked job history endpoints. Studio archived filter, freeze/archive/restore, cloning, side-by-side source comparison (line-position preview capped 500 lines), event history and pinned request/result hash. No hard delete; retention quotas remain and backups/retention policy are separate production gates. Older pre-M12 lifecycle events were not recorded and are not invented. Most recent 200 lifecycle events shown. Tests cover migration, authorization, stale transitions, freeze/archive gates, clone and linked results; browser covers lifecycle. No production deployment, arbitrary Python or real trading.
