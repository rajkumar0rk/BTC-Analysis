# Threat model and execution security

Custom Python strategies are untrusted code, even when generated by a visual editor. M1 contains no user-code execution route. execute_custom_strategy fails closed. SandboxPolicy describes required settings; it does not implement or prove isolation.

Required before enabling custom code: authenticated ownership/authorization; immutable uploaded strategy revision; separate OS-level sandbox for each job; non-root user; no host sockets or credentials; no network; read-only input and isolated writable output; CPU/memory/PID/wall-time/output limits; capability drop and syscall restrictions; controlled dependency images; cancellation kills process group/container; cleanup and audit logs. Validate produced files against strict schema, quotas and path traversal/symlink rules. Trusted publisher writes sanitized result artifacts only, never runs supplied scripts. No pickle or eval of untrusted input. Python AST checks, import restrictions and syntax checks alone are not sandboxing. No production API token in browser, GitHub Pages, strategy environment or logs.

Default deny real trading and exchange writes. Future live execution is a separate permission and service. Paper trading must not share live credentials. M1 tests check policy rejects weakened configuration and custom execution is unavailable. Actual sandbox escape tests, authentication, access-control review and load testing are mandatory later, not claimed completed.

M6 adds authenticated local API, inert stored code, bounded durable jobs and a subprocess for bundled synthetic fixtures only. The subprocess is NOT an untrusted sandbox; custom execution still fails closed. See [backend API](BACKEND_API.md).

M8 authenticated source validation compiles in a bounded subprocess without evaluating bytecode. This is syntax diagnostics only, not an execution sandbox or strategy approval. Custom execution remains disabled.

M17 adds bounded request reception, redacted validation errors, response headers, recovery utility and local service hardening templates. Arbitrary source execution remains fail-closed. See [readiness and deployment](PRODUCTION.md).
