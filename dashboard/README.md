# Backtest Explorer — independent UI and data publishing

Public static GitHub Pages UI; no backend, token, or browser-side GitHub API credential.

- **Backtest dashboard** deploys only index.html, app.js and style.css when UI code changes or on manual dispatch. It does not generate or bundle candles or backtest results. Its Chromium smoke test checks the real cross-origin GitHub Raw data snapshot.
- **Publish backtest data** runs independently after successful supported BTC daily, ETH native ATR and BTC Stage24 research workflows, relevant main data changes, on a six-hour reconciliation schedule, or manual dispatch. It has no Pages permission or deployment step. Unchanged source fingerprints skip export and push. Data publish reads existing recorded ledgers; it never reruns a backtest.
- The public `dashboard-data` branch stores daily candle shards, monthly trade shards, compact curves and index. A validated pointer at `dashboard-data/latest.json` references an immutable Git commit; clients fetch all files at that SHA so mid-refresh updates cannot mix versions. UI checks the pointer on load, every minute while visible, or with Refresh results. GitHub/CDN caching may delay updates briefly.
- ETH ledger is copied from the latest successful Actions artifact and retained in the data branch so artifact expiry does not remove previously published trades. If a newer artifact is unavailable the publisher explicitly retains the last valid ledger and identifies its source run. Unchanged candle partitions reuse existing daily shards. Failed validation leaves the last published snapshot intact. No history rewrite; old snapshots remain recoverable.
- Supported sources: BTC daily audited ledger, ETH native ATR and Stage24 failed auction. Unsupported research files are cataloged, not guessed. New strategy families need an explicit ledger adapter. Other branch results are listed, not automatically merged. Retired experiments remain retired.
- P&L/drawdown in price points, not account equity. EMA overlays are chart references. Missing fills, decisions and dynamic risk trajectories are never fabricated. Public data only; never publish secrets.

Local: install pandas/numpy, obtain the recorded ETH ledger if available, run `python scripts/export_dashboard.py`, `python scripts/verify_dashboard_export.py`, then `python -m http.server 8000 --directory dashboard-dist`. Localhost uses local shards unless `?remote=1` is supplied.

## Curated strategy list
One profitable, full-replay variant per signal family, ranked descriptively by positive months over Jan 2025–Oct 2026, then net, PF and drawdown. Negative configurations and duplicate parameter variants are removed from the published data tree, not erased from Git history. Frozen BTC lock summaries are separately displayed with original source links and cost/validation caveats. No claim of independent validation. The branch catalog lists frozen refs only. Other research engines require explicit adapters.

### Execution replay chart timeframes and indicator metadata

Select 1m, 3m, 5m, 15m, 30m, 1h or 4h display candles. The replay cursor and minute execution are unchanged. The Explorer does not calculate indicators or select them from strategy names. Each source result can supply a run-level indicator_definitions list (id, name, native timeframe_minutes, panel = price or panel, optional parameters), and per-trade indicator_series (id to ordered [UTC Unix seconds, numeric value or null] pairs recorded at observation time) and indicator_values (id to recorded signal value). An empty declaration means indicator-free. Unknown or undeclared series are not displayed. Arbitrary custom indicators work with the same contract. The original CSV exporter preserves optional source columns with these names; the pinned archive importer preserves them if supplied by its source. Publication verification checks schema, identities, ordering and finite values. Legacy archives without metadata display only separately labeled existing signal fields, not inferred full indicator definitions or reconstructed lines. Indicator histories for old runs require export from their actual recorded strategy execution; they are not generated by the UI. No backtest rerun, fabricated signal data or P&L changes.

For reviewed archived sources, the publisher can regenerate continuous histories using a pinned source declaration locator, exact hashed original input partitions, identical indicator engine source and full original warmup. All mapped archived trade signal snapshots must match before publication. Generic source declaration parsing does not execute the strategy or guess its settings. History is sharded by UTC day and the Explorer uses the selected run's metadata and native timeframe; no browser calculation. The first migrated source is the archived 15M Color Reclaim RSI run. Other archives need equivalent original inputs and declaration provenance or pre-recorded series. Derived filter ratios not declared in the original IndicatorBook are not exported by this migration.

### Interactive execution replay chart

The shared time viewport supports mouse/touch drag panning, wheel and pinch zoom, keyboard navigation, crosshair OHLCV/indicator inspection, reset, ruler measurement (signed points, percent, candle intervals and elapsed time), trend lines and horizontal price lines. Drawings are session-local and cleared when selecting a trade; they never change order execution. The full source day is available for panning; earlier UTC days load on demand with matching indicator shards from the same immutable snapshot. History is bounded to 31 loaded days per anchor; use Previous day for farther navigation. Missing days are reported, never synthesized. All panels share a time scale. Panning cannot reveal candles after the original replay cursor. Zoom and pan do not change strategy timeframe or execution results. Browser smoke covers controls and measurement math; touch gestures need device validation.

### Browse mode and smooth chart interaction

Browse history is the default and allows both earlier and later archived candles, including after the selected trade. Execution replay is an explicit mode with start, minute-step, play/pause and seek controls; future candles remain hidden in that mode. Viewport panning is continuous in time (including sub-candle positions), wheel zoom is proportional to input, price scale is held during a drag, and hover uses a cached base canvas instead of recomputing candles and indicators. Archived days and their indicator shards are loaded on demand in either direction, with a 31-day rolling cache. Missing days remain gaps. No result or strategy mutation. Automatic snapshot refresh is suspended while inspecting a trade; use Refresh results to switch snapshots. This is the existing custom renderer, not the TradingView library. Browser CI and real touch performance remain to be verified.

### TradingView Lightweight Charts migration

Execution replay now uses TradingView Lightweight Charts 5.0.9, Apache-2.0, with attribution logo/link and upstream LICENSE/NOTICE. `bash scripts/prepare_dashboard_chart.sh` prepares the pinned standalone bundle locally; CI prepares and packages it with Pages (no runtime CDN dependency). Native candlestick rendering, time/price scales, crosshair, touch/pinch, kinetic scrolling, synchronized resizable indicator panes and series markers replace the custom market-chart renderer. An SVG drawing overlay provides measure, trend and horizontal tools using library time/price coordinates; it is not a full Advanced Charts drawing suite. Browse and causal replay remain separate; raw minutes are truncated at replay cutoff before aggregation. Only declared recorded indicator series are rendered. Missing candle buckets are whitespace. Earlier/later published days are fetched around the viewport with bounded history. Smoke tests exercise native chart identity, zoom, crosshair, measurement and causal replay. Local exported dashboard needs the prepared vendor directory. No backtest logic changed.

### Automatic versioned research publication

Producers use scripts/backtest_bundle.py to emit one backtest.json artifact named btc-analysis-backtest-v1. Include all variants, actual closed-trade rows, original summary, source commit/run/attempt, data provenance and declared native indicator series (empty declarations/series for indicator-free runs). IndicatorRecorder records the real completed-candle IndicatorBook outputs; custom outputs can be supplied explicitly. The trusted main publisher scans named artifacts across repository branches on a 15-minute schedule and on configured workflow completions. It validates successful-run identity, exact file layout, bounded data, trade counts, closed net when applicable and ordered series; never executes research artifacts. Accepted bundles are persisted to dashboard-data _sources before the atomic pointer update. All accepted versions including negative/zero results remain visible, with latest/previous labels. Legacy ranked selection is unchanged; nonstandard older workflows need adapters or adoption of this contract. No missing historical ledgers are fabricated. Publication remains subject to the existing snapshot size limit; retention storage policy needs future scale testing.

The Latest backtests table lists every automatically published version newest-first and opens the corresponding ledger directly. Strategy selection defaults to the newest published run for the instrument; the last nonempty trade month is selected by default. Snapshot polling resumes while a trade is selected; changed snapshots retain the current run, month and trade ID if available, but reset chart viewport. Unchanged snapshots do not reload the chart. Legacy catalog remains separately available.

### Professional chart workspace

The TradingView Lightweight Charts engine now uses a compact top toolbar, dedicated drawing rail, crosshair OHLC and indicator legend, fullscreen/expanded workspace, per-indicator visibility/color/line-width controls and locally saved visual preferences. Known indicator-output types get display-only styles: EMA/SMA/ATR friendly titles, RSI 0–100 scale with 30/50/70 guides, Supertrend step lines colored from the matching recorded direction series, and a direction output hidden by default when its corresponding line is visible (toggle available). Unknown/custom indicators retain generic metadata-driven rendering. No new strategy indicator is computed. Rectangle, ray, Fibonacci, measure, trend and horizontal drawings have undo/redo. Drawings remain session-local; full drawing editing and long/short position tools are not included in this change. The source observations, native timeframe and backtest execution are unchanged.

### Grouped indicator outputs and reference guides

Recognized indicator outputs are grouped by family, exact declared parameters, native timeframe and panel (Supertrend direction is paired across its diagnostic panel). One legend and one visibility control per group; no inferred or newly computed series. Matching Supertrend direction colors the price line, with a bullish/bearish legend value and optional diagnostic toggle in settings, hidden by default. Bollinger/Donchian bands share a price overlay group; MACD line, signal and signed histogram share one pane; stochastic outputs share one pane. RSI and stochastic use 0–100 scales with 30/50/70 and 20/50/80 guides respectively; Williams %R uses −100–0 with −80/−50/−20, CCI includes −100/0/100, MACD zero; ATR remains dynamic. Guides are visual conventions, not strategy thresholds. Unknown indicator outputs are independently rendered. No strategy changes or backtest reruns. Shaded band fills are not part of this patch.

### Unified backtest registry (catalog policy 3)

All published results appear in one paginated, searchable/filterable registry. The migration copies previously verified legacy replay shards and source summaries from the previous publication, keeping their original units, monthly accounting, source links, frozen status and replay IDs. It retires the strategy-specific importer and curated positive-only selection from the active publisher. Existing generic archive adapters still import historical CSV formats; unsupported inputs and missing ledgers are not fabricated. Available unprofitable and summary-only archive configurations are retained without ranking exclusions. New standardized bundles are ingested automatically as before. Summary evidence and realized ledger metrics remain separate. The previous two legacy JSON feeds are copied unchanged solely for old deployed clients during transition; the new UI does not fetch them. The publisher requires the previous verified snapshot (DASHBOARD_PREVIOUS_DATA); a local bootstrap needs that snapshot directory. Publication size limits still apply; deployment waits for policy 3. No trading logic changed.
